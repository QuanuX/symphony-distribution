# D11 primary native-owner maintenance preparation

`d11_native_maintenance.py` carries the existing D09 disposable receipt-owner
campaign onto an explicitly selected primary58 carrier capsule. It adds no core
feature or runtime-owner operation. The original59-carrier supplemental campaign
and all retained results stay unchanged.

The input capsule must pass the original run/artifact transport selection and the
complete source/build/SDK/carrier validator. All51 native receipt owners, six Go
commands and one external runtime/SDK carrier must be present. Their entire
payload assignment is materialized without executing a payload, including the
bounded relative curl link graph. Client and source supplements are not admitted
as substitutes for the selected58 core units.

Owner configuration uses the exact clean core Git checkout identified by the
capsule. The current build plan must match the inherited plan hash. Every
CMakeLists file, CMake script/template, common owner helper and import-proof
input must match both its original and reviewed-export hashes and modes. The
sole dependency-map exception reproduces the exact recorded source-input hash
rebindings and omitted publisher dossier/test inputs in
`cmake/mvp-dependencies.json`. Its retained derived bytes must match that exact
reproduction; every other field, including native component configuration, must
remain unchanged. The original Git map and derived map hashes are both retained.
The helper does not invent a Git tree for the derived public export. This source
is a configuration oracle for the existing owners; the campaign does not claim
a source-free SDK or final installer acceptance result.

A matching ephemeral hosted primary runner and the selected private archive
inspection environment are required. The helper preserves compiler invocation
names, uses private HOME/temp paths, disables CMake package registries through the
existing configuration function, and bounds each child command. It configures
owners without compiling the product graph or running its installed commands.
The original uninstaller inventory must match the selected receipt before any
owner is used against the new disposable prefix.

For every owner, the unchanged campaign checks immutable-version refusal,
shared-root marker refusal, aliased receipts, changed owned bytes, interrupted
removal and retry, empty-version preflight and exact retained-byte recovery.
All51 observations and612 bounded configuration/campaign commands must complete;
a timeout, signal, partial list or empty list cannot pass. Other package bytes,
external files and caller sentinels must survive. Original capsules, source,
helpers, tools and private caller state are checked again before success.

```sh
PINNED_INSPECTION_PYTHON -B qualification/d11_native_maintenance.py \
  --selection SELECTED.json --selection-sha256 SELECTED_SHA256 \
  --artifact VERIFIED_CAPSULE --transport-proof VERIFIED_TRANSPORT.json \
  --source EXACT_CLEAN_CORE_GIT_CHECKOUT --inspection-tools PRIVATE_TOOLS \
  --cmake SELECTED_CMAKE --cc SELECTED_C_COMPILER --cxx SELECTED_CXX_COMPILER \
  --output NEW_PRIVATE_OUTPUT --allow-ephemeral-maintenance
```

For macOS, also supply `--developer-dir SELECTED_XCODE_DEVELOPER_DIRECTORY`.
Linux refuses that Apple-only setting. The workflow supplies the profile's
existing compiler selection and runs with the inspection environment's Python.
Do not supply a developer's active installation as the output.

Only `result.json`, `maintenance-register.json` and `INCOMPLETE.json`, when
present, are portable observations. Raw logs, source and disposable prefixes
remain private. Report and register creation does not authorize production
maintenance or publication. The register is explicitly pending until the entire
campaign succeeds.

Focused tests cover exact58 ownership/count, complete payload correspondence,
read-only file modes, curl chains and link/collision refusal, original/export
configuration equivalence, isolated environments and complete51/612 outcome
requirements. A separate actual reviewed-manifest check reproduces its six
source-input rebindings and two dossier omissions while preserving the complete
configuration projection. These checks do not establish a primary run. Actual qualification
remains pending a verified completed carrier capsule and explicit selection.

Native installation, authenticated shared-root application, live-use/process
retirement, external-runtime ownership, two independently qualified releases and
real upgrade/rollback, native Apple package execution, independent fresh-host
acceptance and publisher trust remain separate gates. Copying the same retained
bytes back is recovery and does not qualify an upgrade or rollback.
